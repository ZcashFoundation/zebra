## [16.1.0] - 2026-11-27

### Added

- `sapling::tree::NoteCommitmentTree::append_batch` and `orchard::tree::NoteCommitmentTree::append_batch` append a block of note commitments at once, reducing aligned subtrees in parallel.
- Add Block::zcash_deserialize_parallel, which decodes large blocks' transactions in parallel, one block at a time, and limits the work spent past an invalid transaction to about the size of the valid prefix.
- Added level-wise batch appends for Orchard and Ironwood note commitment trees, preserving sequential frontiers and completed subtrees. The Merkle hash tables cover all 52 message words without a build-time environment override ([#11846](https://github.com/ZcashFoundation/zebra/pull/11846)).
- Added `ChainTip::best_tip_changed_at`, which returns when the current best tip was published if its hash matches, with a default implementation that returns `None`.

### Changed

- Orchard Merkle node hashing reuses one Sinsemilla hash domain, and `NoteCommitmentTrees::update_trees_parallel` appends each block's commitments as a batch.
- Lowered `transaction::zip317::MARGINAL_FEE` from 1,000 to 400 zatoshis per logical action, which `conventional_fee()` and `unpaid_actions()` follow, and `transaction::zip317::MEMPOOL_TX_FEE_REQUIREMENT_CAP` from 1,000 to 800 zatoshis, so that the size-based minimum fee in `mempool_checks()` never rejects a transaction that pays its conventional fee.
- Documented that `VerifiedUnminedTx::height` must be the tip height that the mempool verified a transaction at, because the block verifier in `zebra-consensus` reuses the mempool's verification of a transaction based on it.

### Fixed

- `founders_reward` no longer panics on a configured Testnet whose slow-start subsidy is not a multiple of 5. It now uses truncating integer division, matching zcashd (`GetBlockSubsidy(nHeight) / 5`). Mainnet and the public Testnet are unchanged. Fixes [#11792](https://github.com/ZcashFoundation/zebra/issues/11792).
