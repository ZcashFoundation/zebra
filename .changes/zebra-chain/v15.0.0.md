## [15.0.0] - 2026-10-22

### Breaking Changes

- Updated `zcash_primitives` to 0.31.0, `zcash_address` to 0.14.0, `zcash_transparent` to 0.11.0, `zcash_protocol` to 0.11.0 and `zcash_history` to 0.6.0, whose `V1`, `V2` and `V3` are re-exported from `primitives::zcash_history`. Their types appear in the public API ([#11614](https://github.com/ZcashFoundation/zebra/pull/11614), [#11784](https://github.com/ZcashFoundation/zebra/pull/11784), [#11877](https://github.com/ZcashFoundation/zebra/pull/11877)).

### Added

- Parse Regtest TEX addresses, which use the `texregtest` HRP. `transparent::Address::from_str` previously accepted only the Mainnet and Testnet HRPs, so Regtest TEX addresses were rejected as unparseable.
- Added the NU7 Mainnet activation height, `parameters::constants::activation_heights::mainnet::NU7` (3,543,405).

### Changed

- Raised the MSRV to 1.89.

### Fixed

- With the `proptest-impl` feature, `Transaction::with_transparent_inputs` no longer leaves an empty transparent bundle when a transaction ends up with no transparent inputs or outputs. An empty bundle hashes differently from an absent one but serializes to the same bytes, which parse as absent, so the txid of a v5 or v6 transaction did not match its serialized form, including in transactions from `fix_generated_transaction` and `Block::partial_chain_strategy`.
- `Transaction::has_transparent_inputs()` and `has_transparent_outputs()` now read the transparent bundle's lengths instead of rebuilding and converting the whole input or output vector, and `coinbase_spend_restriction()` uses the non-allocating check.
- Blocks generated with valid commitments by the `proptest-impl` strategies now have a merkle root that matches their transactions.

### Security

- Bound the upfront `Vec` reservation in `zcash_deserialize_bytes_external_count` (and therefore `zcash_deserialize_string_external_count`, which delegates to it) so a peer-supplied byte count cannot force a large allocation before any payload byte is read. The buffer now grows incrementally as real bytes arrive, mirroring the element-path cap added in PR #10563. CWE-770 ([#10572](https://github.com/ZcashFoundation/zebra/issues/10572)).
- Compute transaction signature hashes from digests cached once per transaction, so verifying a transaction's transparent inputs is linear in their number instead of quadratic. Previously, a single 2 MB transaction with tens of thousands of stub-signed inputs could keep a node's CPU busy for minutes ([GHSA-j4cw-58mj-7w6v](https://github.com/ZcashFoundation/zebra/security/advisories/GHSA-j4cw-58mj-7w6v)).
