## [20.0.0] - 2026-11-27

### Breaking Changes

- Changed the block verifier from `router::init` to trust the `mempool` service passed to `router::init` for consensus. It asks the service for a block's transactions with `mempool::Request::VerifiedTransactionsForBlock`, skips the transaction verifier for the ones it reuses, checks only the rules that depend on the block for them, and adds their miner fees and signature operation counts from the response to the block's totals. A custom mempool service must answer with no transactions, or, when the block's parent is its last seen tip, only with the `VerifiedUnminedTx`s that the mempool transaction verifier from `router::init` returned, unmodified apart from the `time` and `height` that the mempool sets, with the tip height that each one was verified at as `height`. A later fee change, such as a fee delta for prioritisation, must be kept in a separate field, not in `miner_fee`.

### Added

- Exported the `coinbase_is_first`, `difficulty_is_valid`, `difficulty_threshold_is_valid`, `equihash_solution_is_valid` and `merkle_root_validity` block checks from the crate root.
- Added `metrics::describe()`, which describes every metric the crate records, with its unit and a one-line description, `metrics::LABELS`, which lists the label keys of each labelled metric, and `metrics::register_failure_counters()`, which registers the signature and proof failure counters in `metrics::FAILURE_COUNTERS` at zero.
- Added the `zebra.consensus.block.phase.duration_seconds` histogram, which the block verifier records for its block checks, transaction verification, and state commit phases, with a `phase` label. Block proposals are not recorded.

### Changed

- Flush proof and signature batches after 5 ms of idle input while preserving the 100 ms maximum batch latency ([#11673](https://github.com/ZcashFoundation/zebra/pull/11673)).
- Precompute Orchard tree hash tables during verifier initialization; the existing background startup handle covers checkpoint verification and table construction ([#11846](https://github.com/ZcashFoundation/zebra/pull/11846)).
- The semantic block verifier keeps the validation results of block proposals, and commits a solved proposal after checking its proof of work and time, without verifying its transactions again.
- Successful transparent script verifications are cached for the same transaction, spent outputs and network upgrade, without skipping other block checks. The cache uses `parking_lot 0.12` and reports under `zebra.consensus.cache.*` with the `transparent_script` verifier label ([#11939](https://github.com/ZcashFoundation/zebra/pull/11939)).
- The semantic block verifier sends `zebra_state::Request::MiningCandidate` to its state service for a block once its proof of work, Merkle root, time, coinbase position and subsidy are checked, while its transactions are still being verified. It ignores an error response, but a custom or mock state service has to answer the request.
- The block verifier accepts the validation result that `zebra_state::Response::ValidBlockProposal` now carries.
- The block verifier no longer asks the state whether a block with the header of a validated proposal is known: the state rejects a duplicate block when it commits it.
