## [19.0.0] - 2026-10-22

### Breaking Changes

- Updated `zcash_primitives` to 0.31.0, `zcash_address` to 0.14.0, `zcash_transparent` to 0.11.0, `zcash_protocol` to 0.11.0 and `zcash_keys` to 0.17.0, whose `address::Address` is returned by `MinerParams::addr` ([#11614](https://github.com/ZcashFoundation/zebra/pull/11614), [#11784](https://github.com/ZcashFoundation/zebra/pull/11784), [#11877](https://github.com/ZcashFoundation/zebra/pull/11877)).
- `RpcMetricsMiddleware::new` and `RpcTracingMiddleware::new` now require an `Arc<HashSet<&'static str>>` of registered RPC method names, collected from `RpcModule::method_names()`. Unregistered names use the `unknown` method label in request, duration and error metrics, and the `unknown` value in the `rpc.method` span field ([#11837](https://github.com/ZcashFoundation/zebra/pull/11837)).
- Added the `z_converttex` RPC method, which converts a transparent P2PKH address to a ZIP 320 TEX address. Adding a method to the `Rpc` trait is a breaking change for downstream implementers.

### Changed

- The JSON-RPC compatibility middleware that rewrites `InvalidParams` error codes to the `zcashd`-compatible `Misc` code now changes only the error code, preserving the original error's `data` field (previously dropped) instead of rebuilding the response by hand ([#9097](https://github.com/ZcashFoundation/zebra/issues/9097)).
- The JSON-RPC version compatibility middleware no longer copies the request body an extra time when building the rewritten request ([#10574](https://github.com/ZcashFoundation/zebra/issues/10574)).
- `getaddresstxids` and `getaddressutxos` return an `InvalidParameter` error when a query matches more than 100,000 results or `maxEntries` is above 100,000, and the address methods reject more than 10,000 addresses ([#10686](https://github.com/ZcashFoundation/zebra/issues/10686)).
- The indexer's non-finalized state subscription accepts up to 100 known chain tips, up from 10, following the new test-network fork limit ([#11133](https://github.com/ZcashFoundation/zebra/issues/11133)).
- Raised the MSRV to 1.89.

### Fixed

- `Zec` amounts parsed from JSON floats are rounded to the nearest zatoshi instead of being rejected when the float times `COIN` is not an integer. About one in six amounts Zebra itself serializes failed to parse back into `GetBlockchainInfoResponse`, `GetBlockSubsidyResponse` and `getrawmempool` objects. ([#11562](https://github.com/ZcashFoundation/zebra/pull/11562))
- RPC requests with an explicit `"id": null` are now answered. The JSON-RPC compatibility middleware used to drop the `id`, which turned the request into a notification whose response was discarded ([#11625](https://github.com/ZcashFoundation/zebra/pull/11625)).
- `getinfo`, `getnetworkinfo` and `getpeerinfo` read the address book on a blocking thread, so waiting on its lock no longer parks an async runtime worker and stalls other RPC requests ([#11702](https://github.com/ZcashFoundation/zebra/pull/11702)).
- Reject TEX addresses in `getaddressbalance`, `getaddressutxos` and `getaddresstxids`, and in the lightwalletd gRPC address methods that share their validation. They previously parsed successfully but could never match an index entry, so queries returned an empty result instead of an error.
