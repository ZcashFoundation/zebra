## [21.0.0] - 2026-11-27

### Breaking Changes

- `client::GetBlockchainInfoResponse::new` and `methods::BlockObject::new` take a new `nsm_value_balance: Option<GetBlockchainInfoBalance>` parameter after `value_pools`. ([#12325](https://github.com/ZcashFoundation/zebra/pull/12325))
- Added optional static credentials to `config::rpc::Config`, with the public `config::rpc::RedactedString` password type and `config::rpc::StaticCredentialsError` validation error. Update exhaustive struct literals with the new fields or use `..Default::default()`. ([#12403](https://github.com/ZcashFoundation/zebra/pull/12403))
- Added a mempool change subscriber parameter to `RpcImpl::spawn_block_template_updater`, so the block template updater can rebuild templates when the mempool verifies a transaction.

### Added

- Added `client::GetBlockchainInfoBalance::nsm`, which builds the Network Sustainability Mechanism (NSM) value balance entry for a network and height, `monitored` from the block before NU7 activation, and the `client::GetBlockchainInfoResponse::nsm_value_balance` and `methods::BlockObject::nsm_value_balance` accessors for the `nsmValueBalance` field of `getblockchaininfo` and verbose `getblock` responses. The accessors return `None` for responses from nodes that do not report `nsmValueBalance`. ([#12325](https://github.com/ZcashFoundation/zebra/pull/12325))
- Added `metrics::describe()`, which describes every metric the crate records, with its unit and a one-line description, and `metrics::LABELS`, which lists the label keys of each labelled metric.
- Added the `rpc.getblocktemplate.build.duration_seconds` and `rpc.getblocktemplate.first_template.duration_seconds` histograms, and the `rpc.submitblock.outcomes.total` counter with an `outcome` label.

### Changed

- Decode large submitted blocks and block proposals in parallel, off the async executor.
- `submitblock` gives a solved block proposal the decoded transactions of the proposal that Zebra validated, instead of decoding them again.
- `HexData` decodes hex strings with a lookup table, which is faster for block data. Invalid strings get the same errors as before.
- `getblocktemplate` serves a coinbase-only template on a block that is still being verified, while the state publishes early mining work for that block. The block template updater only precomputes templates once the read state answers `ReadRequest::MiningCandidateChanges`.
- The block template updater validates each template it publishes as a block proposal, one at a time. It drops a validation after 30 seconds, or when a template is published on another block. A template that isn't validated is verified like any other block when a miner submits it.
- `submit_block` returns `SubmitBlockErrorResponse::Inconclusive` for a block that is not verified and committed within 30 seconds, instead of waiting until the block is committed or dropped. The block is still verified in the background.
- Kept the `getstandardfee` recommendation at 1,000 zatoshis per logical action on test networks and from Mainnet height 3,590,000, instead of lowering it with `zip317::MARGINAL_FEE` to 400, so that transactions that pay it still relay through nodes that require 1,000.
