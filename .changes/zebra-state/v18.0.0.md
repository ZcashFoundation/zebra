## [18.0.0] - 2026-11-27

### Breaking Changes

- Added the `ReadRequest::CheckBestTipHeader` and `ReadRequest::CheckBestTipBlockCommitments` requests and the `ReadResponse::ValidBestTipHeader` and `ReadResponse::ValidBestTipBlockCommitments` responses, which check a header or block that extends the best tip without committing it; exhaustive matches must handle them.
- Added `Request::MiningCandidate`, `ReadRequest::MiningCandidate` and `ReadRequest::MiningCandidateChanges`, their responses, and the `MiningCandidateGuard` and `MiningCandidateChanges` types, which give miners work on a block as soon as its proof of work is checked. Exhaustive matches on the request and response enums must handle the new variants.
- Added `Request::CommitContextuallyVerifiedBlock` and `ContextuallyVerifiedBlock::rebind`, which commit a block that was validated as a block proposal and then solved, without validating it again. `Response::ValidBlockProposal` and `ReadResponse::ValidBlockProposal` now carry the proposal validation result.

### Added

- Added `metrics::describe()`, which describes every metric the crate records, with its unit and a one-line description, and `metrics::LABELS`, which lists the label keys of each labelled metric.
- Added `From<&ContextuallyVerifiedBlock>` for `ChainTipBlock`, which builds a chain tip block without taking or copying the verified block.
- Added the `state.block_writer.phase.duration_seconds` histogram, which times each phase of committing a checkpoint-verified block, with a `phase` label. `LatestChainTip` now implements `ChainTip::best_tip_changed_at`.
- Added `MiningCandidateGuard::new_for_tests`, with the `proptest-impl` feature.
